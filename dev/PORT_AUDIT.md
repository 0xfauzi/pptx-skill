# Port audit

Every piece of deckgen carried into this skill, with the assumption it rests on and how
that assumption was checked here. A port without a row is not a port. Rows follow deckgen's
ledger protocol: what was adopted, why on merit for THIS skill's goal, what was deliberately
changed, and the evidence.

Goal the merit column is judged against: given any one reference deck (pptx or PDF), generate
dense, expert pitch-book pages that a blind rater files with that reference, including
components the reference never showed, or, given none, pages in a look the agent chooses
under the same hard limits; the agent's judgment does the design and instruments do the
measuring. Rows written before the section "No house" below say "house" for what is now
the reference (one deck, never pooled); they are kept as written, as the record of the time.

Judge distances quoted in a row are the figure measured when the row was written; later rows changed the judge (layout gates, the fixed panel, the house spread) and the emitter, so rows disagree with each other by design. Calibration counts follow the same rule (the "Style fingerprint" row's 147/161 and the "Judge layout gates" row's 157/171 are what those runs measured). The current figures are the re-runnable ones: `dev/proofs/*.build.json` (section 0.083 in `keybank-section.build.json`, round trip 0.056 in `kb3-rt.build.json`, each `judge.total`), and the calibration in `fingerprint.DEFAULT_WEIGHTS` (152/165 with the shipped weights, firms in `dev/oracles/calibration-firms.txt`).

## Not ported, on merit

- deckgen's nine design doctrines as rules (claim titles, label only what matters, one emphasised row per table, same-sized panels are a dashboard, fills as a last resort, a source line on every data page, Harvey balls as a standard exhibit): each contradicts the corpus counts in at least one house type (TARGET_SPEC 23.5). Rewritten as questions plus measured tendencies with counts from TARGET_SPEC Appendix A, with no deck names, in `references/` (storyline, titles-and-text, composition, charts, tables, typography, emphasis-and-decoration); the house's own measured habits decide.

- The walk cost ledger and the full S1B cap set: a shared server's availability bound; a sandbox handling one user's deck needs only the amplification guards.
- The user-correction overlay and recompile machinery: the skill's guide is a JSON file the user or the model edits directly.
