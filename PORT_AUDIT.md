# Port audit

Every piece of deckgen carried into this skill, with the assumption it rests on and how
that assumption was checked here. A port without a row is not a port. Rows follow deckgen's
ledger protocol: what was adopted, why on merit for THIS skill's goal, what was deliberately
changed, and the evidence.

Goal the merit column is judged against: given any reference deck (pptx or PDF), generate
dense, expert pitch-book pages that a blind rater files under the same house, including
components the reference never showed, with the agent's judgment doing the design and
instruments doing the measuring.

Judge distances quoted in a row are the figure measured when the row was written; later rows changed the judge (layout gates, the fixed panel, the house spread) and the emitter, so rows disagree with each other by design. Calibration counts follow the same rule (row 26's 147/161 and row 41's 157/171 are what those runs measured). The current figures are the re-runnable ones: `examples/proofs/*.build.json` (section 0.086, re-run 2026-10-20 on a fresh keybank guide; round trip 0.056 when recorded), and the calibration in `fingerprint.DEFAULT_WEIGHTS` (152/165 with the shipped weights, houses in `oracles/calibration-houses.txt`).

## Design decisions moved from the code to the model

Owner direction: the model designs; scripts resolve roles, write what the spec says,
measure and refuse. Each row is a decision the emitter or the build used to make, what

proofs are the keybank section (`examples/keybank-section.deck.json`), the two bridge
pages (`examples/keybank-bridge.deck.json`) and the house specimen conversions, built and

## Not ported, on merit

- The walk cost ledger and the full S1B cap set: a shared server's availability bound; a sandbox handling one user's deck needs only the amplification guards.
- The user-correction overlay and recompile machinery: the skill's guide is a JSON file the user or the model edits directly.
- The densification search over arrangement moves and the splitter: unbuilt in deckgen too; here the agent proposes arrangements and the solver checks them.
- The ADK agents, budget ledger, gateway, mirror, taskpane: server and add-in concerns.
- `reference_text` advance measurement with HarfBuzz: the capacity table uses the ruler available in the sandbox and says which.
- Motif APPLICATION (deckgen MotifRecipe with geometry_preset, roles, anchor and a param_schema; regions reference recipes by motif_ref and decor.py draws them; spec 01: "a real pathway, not a mined artifact"): the page grammar here has no motif field. The guide's motifs section carries each mined mark with its preset, roles and anchor, and the agent draws a motif as a rule or rect element with those roles where the page calls for it (SKILL.md section 6). A recipe field on regions is a change to the solver's grammar and its oracle; not made.
- Mekko as a native chart (deckgen: column_stacked_100 single-category): not ported; a native 100% stacked column cannot vary category widths, which is the point of a mekko. The mekko approximation (one 100% column per segment at flex weights), the waterfall and the football field are recipes over the general chart spec (`references/design/chart_recipes.md`); the football field is also a component.
- Embedded fonts: deckgen extracts p:embeddedFontLst with libeot and installs per deck before rendering (E03); this sandbox has no libeot, so an embedded face cannot be installed. The digest lists embedded families when a reference carries them, and the agent asks for the font files or records a stand-in under typography.families.substitutes (SKILL.md 2.3).
- Document text in the draft: chrome entries carry up to 60 characters of a line's text and runs carry a 40-character sample, where deckgen's walker lets no document text leave the walk. The text is what tells a footer label from a page-number field and lets the raster instrument match labels; no other field carries text, and the model reads the reference anyway. Recorded, not changed.
- Table column levelling by added line count (review finding): the fitter levels by natural and minimum widths as deckgen's E38 does; a label column can wrap while a one-row header stays whole. Not changed, because the oracle against deckgen's fitter is the port's proof and a new rule needs its own measurement.
- Paragraph rhythm per composition family (review finding): the guide records one modal spacing per role; a reference that spaces an executive page differently from its body pages loses that rhythm. Recorded, not built.
- A capacity command over a page with components: `layout.py capacity` prepares the page as the build does but does not expand components; use the build report's `density` instead.
